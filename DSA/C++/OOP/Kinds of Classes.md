# Kinds of Classes in C++

- The word `class` appears in many C++ constructs: `class`, `struct`, class templates, abstract classes, `final` classes, `enum class`, `template <class T>`, `class Weapon;`. They look alike, but they aren't all classes, and some of them aren't types at all.
- This note lines them up side by side. Each one is explained in detail in an earlier note, linked from its section. This note is about how they differ from each other.

**KEY IDEA:** ask two questions about any of them. **Is it a type?** That is, can you declare a variable of it? And **who writes it: you, or the compiler from a blueprint?** A normal class is a type you write. A class template is a blueprint, and only its instantiations like `Box<int>` are types. An `enum class` is a type, but an enumeration, not a class.

## 1. Normal Classes and Structs

A normal class is one concrete type, written by you, with all of its member types fixed:

```cpp
class IntBox {
public:
    explicit IntBox(int v) : value_(v) {}
    int get() const { return value_; }
private:
    int value_;
};
```

The compiler compiles `IntBox::get` once, in whichever `.cpp` file defines it. Other files only need the declaration to call it.

`struct` is the same thing with public members by default (see [`class` vs `struct`](<Classes and Objects.md#class-vs-struct>)). Everything in this note that applies to classes applies to structs too.

## 2. Class Template vs Normal Class

A **class template** is a blueprint the compiler uses to write classes. The type is left as a placeholder:

```cpp
template <typename T>
class Box {
public:
    explicit Box(T v) : value_(v) {}
    T get() const { return value_; }
private:
    T value_;
};
```

`Box` by itself is **not a type**, so you can't declare a variable or parameter of type `Box`:

```cpp
void show(Box b);   // ERROR: use of class template 'Box' requires template arguments;
                    //        argument deduction not allowed in function prototype
```

Supplying the type argument makes the compiler **instantiate** the template: it substitutes the type for `T` and produces an ordinary class:

```text
template <typename T> class Box { T value_; ... }       blueprint: parsed, no machine code
          |
          |  the program uses Box<int> and Box<std::string>
          v
class Box<int>         { int value_; ... }               a real class
class Box<std::string> { std::string value_; ... }       another, unrelated real class
```

The generated classes are as separate as if you'd written `IntBox` and `StringBox` by hand. They share no code and can't be assigned to each other:

```cpp
Box<int> a(1);
Box<double> b(2.0);
b = a;              // ERROR: no viable overloaded '='
```

| | Normal class | Class template |
|---|---|---|
| Is it a type? | Yes | No. `Box<int>` is |
| When is code generated? | When its `.cpp` file compiles | When a program uses `Box<SomeType>` |
| Where do member bodies go? | Usually a `.cpp` file | The header, so users can instantiate them (see [Why Templates Live in Headers](<../Fundamentals/Templates.md#3-why-templates-live-in-headers>)) |
| How many compiled copies? | One | One per type argument used |
| When are type errors found? | When the class compiles | Errors that depend on `T` appear only at instantiation |

### "Class Template" vs "Template Class"

The standard's term is **class template**: the blueprint. "Template class" is a common informal name for the same thing. Some writers use it for an instantiation like `Box<int>` instead. The standard calls that a **specialization** of the template.

### Members Are Instantiated Only When Used

Instantiating `Box<int>` generates the class layout and member declarations. A member function's **body** is only instantiated if something calls it. So a class template can be used with a type that only some of its members support:

```cpp
struct NoDraw {};

template <typename T>
struct Holder {
    T item;
    void draw() { item.draw(); }   // needs T to have draw()
};

Holder<NoDraw> h;   // OK: draw() is never called, so its body is never instantiated
h.draw();           // ERROR: no member named 'draw' in 'NoDraw'
```

`std::vector<T>` relies on this. `std::vector<std::unique_ptr<T>>` works even though `unique_ptr` can't be copied, as long as you never call the members that copy elements.

## 3. Function Templates vs Class Templates

### What a Function Template Is

A **function template** is the same idea applied to a single function: a blueprint the compiler uses to write functions. A normal function has fixed parameter types, so handling another type means writing another overload by hand:

```cpp
int    max_of(int a, int b)       { return a > b ? a : b; }
double max_of(double a, double b) { return a > b ? a : b; }   // same body, copied
```

A function template writes the body once, with `T` as a placeholder:

```cpp
template <typename T>
T max_of(T a, T b) {
    return a > b ? a : b;
}
```

Like `Box`, `max_of` by itself isn't a function yet. The compiler instantiates it for each type it's called with:

```text
template <typename T> T max_of(T a, T b)       blueprint: parsed, no machine code
          |
          |  max_of(3, 7)      max_of(2.5, 1.5)
          v
int    max_of<int>(int, int)                   a real function
double max_of<double>(double, double)          another real function
```

The difference from a class template is visible at the call site. The compiler works out `T` from the arguments, so calls look like calls to a normal function. `max_of(3, 7)` uses `max_of<int>`. When the arguments disagree, name `T` explicitly:

```cpp
max_of(3, 7.5);           // ERROR: deduced conflicting types for parameter 'T' ('int' vs. 'double')
max_of<double>(3, 7.5);   // 7.5
```

Details, including C++20's `auto` parameters (a shorter way to write function templates), are in [Function Templates](<../Fundamentals/Templates.md#1-function-templates>).

### Side by Side

Both are blueprints, but they're used differently:

| | Function template | Class template |
|---|---|---|
| Example | `template <typename T> T max_of(T, T);` | `template <typename T> class Box;` |
| Produces | Functions | Classes |
| Template arguments | Deduced from the call arguments: `max_of(3, 7)` | Written out, `Box<int>`, or deduced from constructor arguments (CTAD, C++17) |
| Overloading | Several templates may share a name | One class template per name |
| Partial specialization | Not allowed | Allowed |

Class template argument deduction (CTAD) lets the compiler work out `T` from the constructor's arguments:

```cpp
Box b(3.14);   // Box<double>
```

Only function templates can be **overloaded** by template parameter list:

```cpp
template <typename T>             void f(T);      // OK
template <typename T, typename U> void f(T, U);   // OK: a second, overloaded f

template <typename T>             struct Pair;
template <typename T, typename U> struct Pair;    // ERROR: too many template parameters in template redeclaration
```

Only class templates allow **partial specialization**, meaning a separate version for a whole family of arguments. [Specialization](<../Fundamentals/Templates.md#7-specialization>) covers full specialization, which handles one exact type:

```cpp
template <typename K, typename V> struct Table      { /* general version */ };
template <typename V>             struct Table<int, V> { /* used for any Table<int, V> */ };

template <typename K, typename V> void store(K, V) {}
template <typename V> void store<int, V>(int, V) {}
// ERROR: function template partial specialization is not allowed
```

For functions, overloading does the same job: write a separate `template <typename V> void store(int, V)`.

## 4. Members of Templates: Two Different Things

Templates can contain functions in two different ways, and the rules differ.

**A member function of a class template.** `Box<T>::get` has no template parameters of its own. Once `T` is fixed, `Box<int>::get` is one ordinary function, so it **can be `virtual`**:

```cpp
template <typename T>
struct Source {
    virtual ~Source() = default;
    virtual T next() = 0;               // OK: Source<int> has exactly one next()
};

struct Counter : Source<int> {
    int next() override { return n_++; }
private:
    int n_ = 0;
};
```

**A member function template.** It has its own template parameters, and it can appear in a normal class or in a class template:

```cpp
struct Logger {
    template <typename T>
    void log(const T& value);           // log<int>, log<std::string>, ... one function per T used
};
```

A member function template **can't be `virtual`**:

```cpp
struct Logger {
    template <typename T>
    virtual void log(const T&);         // ERROR: 'virtual' cannot be specified on member function templates
};
```

A vtable has one slot per virtual function, and its layout is fixed when the class is compiled (see [Virtual Functions and Vtables](<Virtual Functions and Vtables.md>)). `log` could become any number of functions, depending on which types callers use, so there's no fixed set of slots to reserve.

## 5. Abstract and `final` Classes

These are ordinary classes. The difference is how they relate to inheritance:

- An **abstract class** has at least one pure virtual function (`= 0`). It's a type, so you can have pointers and references to it, but you can't create objects of it:

    ```cpp
    struct Shape { virtual double area() const = 0; };
    Shape s;   // ERROR: variable type 'Shape' is an abstract class
    ```

    A class made only of pure virtual functions is used as an **interface**.

- A **`final` class** can't be used as a base class:

    ```cpp
    struct Guard final {};
    struct Elite : Guard {};   // ERROR: base 'Guard' is marked 'final'
    ```

The `= 0` and `final` keywords themselves are covered in [Function Specifiers](<Function Specifiers.md>).

## 6. Nested and Local Classes

A class can be defined inside another class. Its full name includes the outer class, and access control applies to it like any other member:

```cpp
class List {
public:
    struct Node { int value; Node* next; };   // List::Node
private:
    Node* head_ = nullptr;
};

List::Node n{1, nullptr};
```

This is how containers provide helper types: `std::vector<int>::iterator`, `std::map<K, V>::value_type`. A class can also be defined inside a function, as a **local class**, visible only in that function.

## 7. `enum class`: Not a Class

`enum class` defines a **scoped enumeration**. The `class` keyword only means "the enumerators live inside the enum's scope", as in `AlertState::Idle`, and "no implicit conversion to `int`" (see [Enums and Type Aliases](<../Fundamentals/Enums and Type Aliases.md#enum-class-scoped-c11>)). `enum struct` means exactly the same thing.

It has none of a class's features: no member functions, constructors, data members, or inheritance. Each value is just an integer:

```cpp
enum class AlertState : unsigned char { Idle, Suspicious, Alerted };   // sizeof(AlertState) == 1

enum class Bad { A, B; int f(); };
// ERROR: expected '= constant-expression' or end of enumerator definition
```

Behavior for an enum goes in free functions instead:

```cpp
const char* to_string(AlertState s) {
    switch (s) {
        case AlertState::Idle:       return "Idle";
        case AlertState::Suspicious: return "Suspicious";
        case AlertState::Alerted:    return "Alerted";
    }
    return "?";
}
```

Python is different here. `class Color(Enum)` **is** a real class, and its members can have methods. In C++, an enum that needs methods or extra data has to be a `struct` or `class` instead.

| | `class` / `struct` | `enum class` |
|---|---|---|
| What it is | A class | A scoped enumeration |
| Values | Any objects you construct | A fixed set of named integer constants |
| Member functions, constructors | Yes | No |
| Inheritance | Yes | No |
| Size | Sum of members plus padding | Size of the underlying integer type |

## 8. `class` That Doesn't Define a Class

Two more uses of the keyword don't define a class at all:

- **In a template parameter list**, `class` and `typename` are interchangeable. `template <class T>` accepts **any** type, including `int`, so the keyword doesn't mean `T` must be a class.
- **In a forward declaration**, `class Weapon;` names a class that's defined somewhere else. It's enough for pointers and references, but not for creating objects or calling members (see [Forward Declarations](<../Fundamentals/Headers and Source Files.md#forward-declarations>)).

## How Python Compares

| C++ | Python | Difference |
|---|---|---|
| `class` / `struct` | `class`, `@dataclass` | C++ fixes the members at compile time |
| Class template `Box<T>` | `class Box(Generic[T])` | Python keeps **one** runtime class, and `Box[int]` is only a type-checker label. C++ generates a separate class per `T` |
| Abstract class | `ABC` with `@abstractmethod` | C++ reports the error at compile time |
| `final` class | `@typing.final` | Python only checks it with type checkers |
| `enum class` | `class Color(Enum)` | Python's enum is a real class with methods. C++'s is a set of integers |

> Unreal's naming prefixes encode these kinds, so the name tells you what you're looking at: `T` for templates (`TArray<T>`, `TSubclassOf<T>`), `E` for enums (`EGuardState`, usually an `enum class` with `UENUM()`), `I` for interfaces (`IInteractable`), `F` for plain structs and classes (`FVector`, `FHitResult`), `U` for classes derived from `UObject`, and `A` for classes derived from `AActor`.

## Summary

1. A normal class is a type you write. A class template is a blueprint. Only its instantiations, like `Box<int>`, are types.
2. Each instantiation is a separate, unrelated class. Member function bodies are only instantiated when used.
3. A function template is a blueprint for functions, as a class template is for classes. Function templates deduce their arguments from the call and can be overloaded. Class templates can be partially specialized, and deduce arguments only from constructors (CTAD).
4. A member function **of** a class template can be `virtual`. A member function **template** can't.
5. Abstract and `final` classes are ordinary classes with inheritance rules attached.
6. `enum class` is a scoped enumeration, not a class: no members, no inheritance, just named integers.
7. `class` in `template <class T>` means "any type", and `class Weapon;` only names a class defined elsewhere.
