Always Try to disambiguate the edges of a problem by asking followup questions and understanding the space a problem exists in before even attempting to solve it.

This helps clear up the requirements and set expectation for a possible solution.

For DSA Coding Question, it is thinking of input data, constraints on the data and edge cases.
For System Design, it may be getting info about the product/service, users, traffic(Requests/sec), etc.

Use the CARL method
Context -> Action -> Results -> Learning

It is inspired form the STAR method and context groups situation and task under context and adds the learning part.
